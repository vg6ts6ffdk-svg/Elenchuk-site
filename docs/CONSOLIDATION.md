## Единые действующие решения

- Задание: [мастер-промпт 5.0](ROSEEN-MASTER-PROMPT.md); правила исполнителя: ../AGENTS.md.
- Сервис + магазин + кабинет в одном проекте, а не новый независимый сайт.
- Москва и Московская область; остальные регионы по согласованию. Не выдумывать контакты, реквизиты, товары, цены и наличие.
- Графический РОСИН в header, ROSEEN в footer, favicon R. Контуры из assets/brand не изменены; контрольные суммы в manifest.json. Запрещены текстовая подмена и возврат прежней белой плашки.
- Палитра согласованного брендбука: Navy/Blue/White. Старые RAL 6018 и ранняя graphite-палитра не являются текущим заданием.
- Motion по мастер-промпту: неподвижная геометрия логотипа, отдельная последовательность RO/SE/EN, reduced-motion; без параллакса и magnetic на основном сайте.
- Обе CC1-анимации — исследовательские варианты, не подтверждённая техническая модель и не часть production. Уточнения владельца и ограничения: ../prototypes/README.md.
- Брендбук и мастер-пакеты сохраняются в отдельной исходной задаче; не добавлять в публичный репозиторий личные переписки, банковские сведения, ключи, письма или неподтверждённые материалы.

## Разделение сред и готовности

Preview каталога включается только существующим флагом. Оформление заказа, реальные платежи и отправка клиентских уведомлений не включены. Каталог пуст до получения реальных данных. Persistent order repository реализован отдельно и не подключён к checkout.

Сведения о неработавшем Vercel API от 18 сентября относятся к тому старому deployment, а не автоматически к текущему main. Инфраструктуру Render/Neon/Vercel, секреты, production-базу, DNS и почту при объединении не изменяли. Удалённая заявка, сохранность через redeploy и production QA требуют отдельной актуальной проверки.

## Проверка и дальнейшая работа

Запускать проверки исходников, тесты, сборку и проверку dist как без магазина, так и с `ROSEEN_STOREFRONT_PREVIEW=1`. Дополнительные regression tests проверяют логотипы в исходниках и непубликацию prototypes. CI браузерных проверок запускается на общем PR.

Дальнейшие изменения вести из этой общей ветки, предварительно получая свежий GitHub head. Не перезаписывать ветки силой и не переносить весь старый worktree поверх неё. Актуальный результат проверки фиксируется в [EXECUTION-STATUS.md](EXECUTION-STATUS.md); успешный build не равен готовому production-магазину.
