# Подключение inSales к ROSEEN

Выбор владельца: Россия, RUB, inSales. Сайт и его дизайн остаются в существующем репозитории. inSales станет источником товарных данных и системой управления магазином после подключения и проверки. Текущее состояние — подготовленное чтение каталога, не запущенные продажи.

## Что уже работает в коде

- Серверное чтение товаров и вариантов через официальные `GET /admin/products.json` и `GET /admin/products/:id.json`.
- Проверка базовой валюты товара: коды рубля inSales `RUB` и `RUR` приводятся к внутреннему `RUB`; остальные валюты отклоняются. Точное преобразование рублей в копейки, проверка артикулов и остатков. Неизвестный остаток остаётся неизвестным.
- Явное сопоставление категорий, производителей и единиц продажи. Совместимость с оборудованием не выводится из названия.
- Все полученные варианты сохраняются черновиками. Скрытые и архивные товары пропускаются; комплекты требуют отдельной проверки.
- Закрытый административный `/api/store-admin/status` показывает наличие настройки inSales без ключей, адреса аккаунта и личных данных. `configured: true` означает наличие параметров, а не успешную проверку доступа.
- CLI сохраняет отдельный файл вне репозитория с правами `0600` и не перезаписывает существующий файл. Ошибочный импорт не создаёт файл и не меняет действующий каталог.

## Проверка через административный API ROSEEN

Методы доступны только с действующей административной сессией ROSEEN и включённой витриной. Сервер использует собственные параметры среды; адрес магазина и ключи из тела запроса не принимаются.

| Метод | Назначение | Подтверждённый результат |
| --- | --- | --- |
| `GET /api/store-admin/status` | Проверить наличие конфигурации | `configured` сообщает только наличие трёх параметров. |
| `POST /api/store-admin/insales/connection-check` | Выполнить один запрос чтения товара | `connected: true` и `catalogReadVerified: true` означают успешный ответ API с ожидаемой структурой. Пустой каталог тоже допускается. |
| `POST /api/store-admin/insales/import-preview` | Проверить каталог со словарями в `mapping` | Количество черновиков, ошибки и первые 100 проверенных строк. `commitAllowed` и `checkoutEnabled` остаются `false`. |

Успешная проверка подключения доказывает доступ к чтению товаров, а не готовность продавца, оплаты, доставки или продаж. Исходные ответы, закрытые поля, HTML-описания, закупочные цены и ключи в результат не включаются. Неверная строка запрещает весь предварительный импорт: частичного списка товаров не будет.

Ошибки административной сессии дают HTTP 401; ненастроенное подключение или неверные API-реквизиты — HTTP 503 с кодом причины. Некорректный ответ провайдера — HTTP 502. При ограничении API возвращаются HTTP 429 и безопасный `Retry-After`. Ошибки соответствий — HTTP 400, товарных данных — HTTP 422. Автоматических повторных запросов нет.

Оба действия делят лимит 5 запусков за 5 минут на IP. В одном процессе одновременно выполняется только одна проверка/загрузка. Один ответ провайдера ограничен 4 МБ и 10 секундами; полная загрузка — 16 МБ, 30 секундами, 5000 товарами и 5000 входящими вариантами, включая ошибочные и скрытые записи. Этот предел проверяется до формирования отчёта об ошибках. Отмена таймера прерывает HTTP-запрос, а не оставляет его выполняться в фоне.

JSON со словарями для API ограничен 32 КБ. Для большого файла соответствий используется CLI. Список в ответе API — ограниченный предпросмотр; полная выгрузка в приватный файл выполняется через CLI.

## Подключение аккаунта

1. Владелец входит или регистрируется на `https://accounts.insales.ru/`. Код подтверждения и принятие условий сервиса выполняет владелец. Подписка оплачивается отдельно по его решению.
2. В кабинете подтверждаются магазин, валюта и сведения продавца. Для интеграции нужен технический домен аккаунта `*.myinsales.ru` и отдельные API-реквизиты для чтения каталога, не пароль от кабинета. Условия доступа к API проверяются на выбранном тарифе.
3. Реквизиты сохраняются только в приватной конфигурации среды, где запускается коннектор. Пароли, ключи и исходные выгрузки не отправляются в чат и не коммитятся в Git.

Параметры среды: `INSALES_SHOP_HOST`, `INSALES_API_KEY`, `INSALES_API_PASSWORD`. Секреты передаются провайдеру в HTTP-заголовке, по HTTPS. Коннектор не принимает домен из браузерного запроса и не следует перенаправлениям.

## Предварительная загрузка каталога

Сначала создаётся приватный JSON-файл соответствий. Он содержит три словаря, ключи которых берутся из реального аккаунта:

```json
{
  "categories": {},
  "manufacturers": {},
  "units": {}
}
```

В `categories` ключ — ID категории inSales, значение — существующая категория ROSEEN: `belts`, `brushes`, `filters`, `electronics`, `sensors` или `service-kits`. В `manufacturers` ключ — ID товара inSales, значение — подтверждённый производитель. В `units` ключ — единица inSales, значение — подтверждённая единица продажи. Отсутствующие соответствия дают ошибку вместо предположений.

При уже настроенной приватной среде:

```sh
npm run store:insales:preview -- --mapping /private/mapping.json --output /private/drafts.json
```

Пути в команде — обозначения приватных файлов, их нужно заменить реальными. Выходной каталог должен существовать и находиться вне всего репозитория ROSEEN. CLI использует тот же загрузчик и лимиты, что административный API. По алгоритму inSales каждый запрос читает первую страницу, до 100 записей, с курсором `updated_since`/`from_id`. Начальный курсор — 1 января 1970 года UTC; затем берутся `updated_at` и ID последнего товара. Загрузка заканчивается только на пустом ответе и ограничена 51 запросом, а не выдаёт неполную выгрузку при достижении лимита. Параметры дат и часового пояса кодируются в URL.

При одинаковом времени обновления ID сравниваются без потери точности больших строковых значений. Отсутствующий timestamp, нарушение порядка, повтор товара или игнорирование курсора останавливают загрузку — нужно проверить источник и повторить её на стабильном каталоге. Удаление ранее прочитанного товара не сдвигает непрочитанные товары за границу следующей страницы. Это чтение для черновиков, а не атомарный снимок наличия на момент продажи. Сервер возвращает ошибки авторизации и ограничения частоты без содержимого ответа провайдера; автоматические повторные запросы не выполняются.

Результат — файл в модели `commerce/catalog.mjs`: `state: draft`, `verifiedAt: null`, совместимость не подтверждена. Публикация и продажи не разрешаются этой командой. Исходные HTML-описания, изображения, закупочные цены и частные поля в файл не включаются. Медиа потребуют отдельного проверенного импорта.

## До запуска продаж

Следующий этап после подключения — проверить реальный каталог, добавить подтверждённые медиа/совместимость и реализовать управляемую публикацию. Затем соединить постоянное хранение заказов, резервирование, серверный пересчёт, оплату/чеки, доставку и клиентские права с выбранным аккаунтом.

Пока API чтения не превращается в обработчик заказов. Ни заказ, ни резерв, ни платёж в inSales этот коннектор не создаёт. Оформление заказа останется закрытым до выполнения всех требований `LAUNCH_REQUIREMENTS`, проверки продавца и изолированного E2E. Платёжный провайдер и тариф доставки пока не выбраны.

## Проверка и откат

Тесты коннектора и импорта используют только синтетические данные и подставной транспорт. Они проверяют авторизацию, ошибки провайдера, валюту, дубли, пагинацию, приватный вывод и сохранение блокировки checkout; они не подтверждают работу настоящего аккаунта.

Для отключения загрузки достаточно убрать три параметра inSales из приватной среды. Не выполняются миграции, удаления, записи в провайдера или изменения действующего товарного файла. Возврат к предыдущей версии кода делается обычным revert проверенного коммита.

Источники контракта, проверенные 4 октября 2026:

- https://api.insales.ru/ — Products: Get products / Get product, варианты, базовая валюта цены и остатки.
- https://www.insales.ru/collection/doc-rabota-s-api-i-prilozheniya/product/kak-sdelat-zapros-k-api — отдельные API-реквизиты, Basic Auth, технический домен, предел запросов и `Retry-After`.
- https://www.insales.ru/collection/doc-rabota-s-api-i-prilozheniya/product/poluchenie-tolko-izmenivshihsya-dannyh — порядок `updated_since`/`from_id`, исключение уже прочитанных ID и продолжение до пустого ответа.
- https://www.insales.ru/collection/primery-raboty-s-dannymi-magazina/product/multivalyutnost — обозначение рубля `RUR` в inSales. Базовая валюта конкретного товара проверяется отдельно от валюты витрины.
