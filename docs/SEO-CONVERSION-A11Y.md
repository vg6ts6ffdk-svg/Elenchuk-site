Утверждение verified требует проверки материала человеком.
6. **Выпустить проверенный PR.** Проверки → Preview → согласованный релиз → отдельный успешный Pages workflow → Prod QA на roseen.ru. Сначала обновить и проверить backend: прежний multipart-лимит четырёх полей не принимает новую форму с honeypot; новая версия принимает пять. Vercel READY подтверждает отдельную сборку, а не публикацию на основном домене. После выпуска повторить ответы сервера, визуальные проверки и аналитические события на фактической версии.

## Готовые фрагменты и точки подключения

### Структурированные данные

Разметка вставляется в готовый HTML при сборке; для её появления не нужен JavaScript браузера.

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "Organization",
      "@id": "https://roseen.ru/#business",
      "name": "РОСИН",
      "alternateName": "ROSEEN",
      "url": "https://roseen.ru"
    },
    {
      "@type": "Service",
      "@id": "https://roseen.ru/diagnostika.html#service",
      "name": "Диагностика",
      "serviceType": "Диагностика",
      "url": "https://roseen.ru/diagnostika.html",
      "provider": { "@id": "https://roseen.ru/#business" }
    }
  ]
}
</script>
```

Ремонт, обслуживание и инжиниринг создаются аналогично с собственными URL. Реальная сборка дополнительно включает описания, логотип и крошки.

Для полноценного LocalBusiness используется готовая функция, а не адрес-заглушка:

```js
import { businessSchema } from './scripts/site-pages.mjs';
const jsonLd = {
  '@context': 'https://schema.org',
  ...businessSchema(verifiedSettings)
};
// verifiedSettings.address:
// { streetAddress, addressLocality, addressCountry, postalCode }
// verifiedSettings.telephone: подтверждённый номер в формате E.164
// verifiedSettings.geo: { latitude, longitude }
// verifiedSettings.openingHoursSpecification:
// [{ dayOfWeek: ['Monday', ...], opens: '09:00', closes: '18:00' }]
// Часы выше — формат записи, не фактический график ROSEEN.
```

На faq.html функция формирует этот тип из опубликованных вопросов:

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [{
    "@type": "Question",
    "name": "Можно ли сначала сделать диагностику?",
    "acceptedAnswer": {
      "@type": "Answer",
      "text": "Да. Диагностика отделена от ремонта: сначала определяем неисправность и согласовываем дальнейшие действия."
    }
  }]
}
```

FAQPage остаётся типом Schema.org. Google прекратил показ FAQ rich results 7 мая 2026 и удалил соответствующее руководство в июне. Поэтому наличие валидной схемы не является обещанием FAQ-сниппета или роста позиции. Проверить синтаксис в Schema Markup Validator; применимые Google-типы — дополнительно в Rich Results Test. Отсутствие FAQ rich result не считать ошибкой схемы.

## Аналитика и цели

1. В Метрике создать счётчик для https://roseen.ru, часовой пояс Москва, включить Вебвизор. Запись полей отключить; в коде дополнительно используются ym-disable-keys и ym-hide-content. Пока нет ID, никаких внешних запросов не происходит.
2. В GA4 создать ресурс и веб-поток, получить Measurement ID вида G-…. В Enhanced Measurement отключить Form interactions, Outbound clicks и Site search: они могут отправлять полный адрес ссылки или введённый поисковый текст. Для сценария заявки используется generate_lead только после успеха API; телефон и мессенджеры отслеживаются собственными обработчиками.
3. Внести ID в site-settings.json → analytics. Номер Метрики — положительное целое, GA4 ID — строка G-…. Настройки рекламной персонализации остаются выключенными. Аналитика запускается после выбранного разрешения и только на основном домене.
4. Создать цели/ключевые события:

| Действие | Метрика: целевое событие | GA4 | Что считается результатом |
|---|---|---|---|
| Заявка сохранена | request_sent | generate_lead | HTTP success + целочисленный ID заявки |
| Телефон | phone_click | phone_click | Клик по реальной ссылке tel: |
| Мессенджер | messenger_click | messenger_click | Клик по реальной ссылке Telegram/WhatsApp/другого поддерживаемого канала |

Сделать generate_lead основным ключевым событием GA4. Клики — отдельные микроцели; они не доказывают разговор или продажу. Не добавлять выдуманную денежную ценность лида. Публичные телефон и мессенджеры должны быть подтверждены перед появлением ссылок.

Контакты, текст обращения, ID заявки и адрес целевого мессенджера не отправляются в параметры событий. Из URL посещения удаляются query/hash; очищенные page_location/page_referrer установлены в общей конфигурации GA4 для последующих событий. После включения проверить фактические payload. UTM/атрибуция потребуют отдельной безопасной конфигурации: текущий вариант намеренно не передаёт произвольные query-параметры.
