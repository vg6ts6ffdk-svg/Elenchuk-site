# ADR — preview catalogue boundary (20 September 2026)

Status: implemented preview boundary; commerce platform NOT selected.

The existing stack is static HTML generated by Node plus Express. Preserve its routes, production deployment and service API. The new `storefront/` layer renders a read-only catalogue snapshot to separate category/product pages, with browser filtering and a guest cart. This demonstrates and tests the site integration without choosing an unapproved commerce vendor or creating fake prices.

## Boundaries
- `storefront/catalog.json`: currently empty, trusted server/build snapshot. It is not a merchant admin or a live inventory database. No filesystem write/import endpoint exists.
- `storefront/settings.mjs`: explicit public projection and preview gate. Private evidence is not sent to browsers.
- `storefront/render.mjs`: HTML templates escape untrusted text. Only published records generate product URLs. No products or Product/Offer SEO claims exist until actual data is supplied; all preview pages are noindex/nofollow.
- `store-core.js`: URL filtering and minimal guest cart serialization; it cannot authorize a purchase.
- `/api/store/quote`: trusted server-side goods calculation using the earlier commerce contract; it always declares checkout disabled, does not reserve stock and does not create an order. Read-only routes do not initialize the service database. Existing origin guard and JSON size limit remain in place.
- `public-files.mjs`: optional store routes/media only in preview. `server.js`, tests, docs, source snapshots and internal catalogue stay out of the public allowlist.

## Production controls
No production override is provided for preview mode. Do not turn this flag into a live-shop switch. Before release, replace the trusted snapshot input with an approved provider adapter, resolve persistent storage, seller/legal/tax settings, verified prices/stock, atomic reservations, idempotent orders/payments/refunds, delivery and access controls. No existing service database migration is required by this increment.

## Rollback and ongoing work
PR #7 remains a draft. All changes are in `feat/roseen-platform-v5`; main remains at the audited SHA until a separately agreed release. Revert the preview increment or disable preview routing to remove storefront exposure; this cannot remove orders because none are created.

Motion uses MDN-documented Web Animations and guarded sessionStorage; browser QA uses official Playwright 1.63.0.
